# Galaxy Tools → Pane 迁移计划

状态：已在 `codex/pane-native-migration` 开工。性能原型已完成；Pane 已接入网卡速率、便签、截图历史和三类桌面卡片。进程流量服务和原生截图均有独立内部预览产物，未纳入标准安装包；流量服务未注册。下文标为“待确认”的决策不等同于服务安装授权。

## 首版剩余验收

已有合并内测包，隔离安装、应用测试和载荷验证已有记录；这些不算正式安装、真机操作或实际采集通过。首版剩余工作按下列门槛收口：

- [ ] **Windows 界面。** 由 6.1 Terra 从[验收交接](#61-terra-验收交接)开始：优先查鼠标所在单屏的三卡、全屏切换和整屏闪烁，再验收截图贴图、便签、OCR、剪贴板及备份恢复。无需等服务签名即可先测无采集场景。
- [ ] **流量服务。** 在独立 Windows 测试环境用正式发布证书，验证 `PaneTraffic` 手动首次安装、普通账号 `own` 授权、真实 ETW 收发归属和历史落盘，以及断开后手动重连与无服务时的状态。服务升级、自动回滚和双屏同时展示不计入首版。
- [ ] **整组性能。** 采集验证通过后，再用相同负载对比 Galaxy 与 Pane，分别报告三卡和服务的内存、CPU、切换指标和长跑稳定性。立项原型和本地 SQLite 结果不代表正式版本的收益。
- [ ] **发布。** 确认独立 fork 的身份与发布通道，完成 OCR 引擎授权或替换、随包许可清单及正式签名，再用正式安装包复验安装、应用升级、卸载和数据保留。

## 目标与边界

- 以 Pane 的 WinUI/NativeAOT 宿主为底座，建立独立维护的 fork。优先复用 Pane 的模块生命周期、窗口、启动器、快捷键和设置；已有能力只补缺口。按用户任务验收，不复刻 Galaxy 的界面、入口、操作步骤或代码结构；不能覆盖的任务单独确认。
- 首版只做内置能力。不承接 Galaxy 的旧插件、CLI 或 MCP 兼容，不做第三方市场、插件运行时或网页卡片宿主。对原先依赖网页插件的内置任务，优先用 Pane 原生交互替代；不能等价的条目标明差异，不算完成。
- 文件搜索不在本轮迁移范围内。不加限定目录搜索，沿用 Pane 现有全局文件搜索，不改入口、关键词行为、界面或索引。
- 使用新数据目录和模型，不做旧数据无损导入，也不自动读写或清理 Galaxy 数据。Pane 自己的备份、恢复和卸载保留数据是独立需求，不等同于旧格式兼容。
- 不做 Galaxy 兼容或回退。首版先跑通内置功能、卡片桌面和流量服务首次安装。沿用 Pane 现有的保存和安装保护；操作失败提示原因，由用户决定是否再试，不新增防御性功能、自动重试、自动回滚、服务升级替换或降级流程。
- 计划以 Galaxy `fd8f11e` 和 Pane `4de2976` 的源码为盘点起点。性能报告对应 Galaxy 0.1.7 已安装包和 Pane 开发原型，不是这两个源码版本的功能等价对照。

## 性能立项依据

见[性能实测](pane-migration-performance.md)。同机三卡实测，私有工作集减少 **384–420 MiB（71.8%–76.0%）**，三个场景均超过 **100 MiB 且 30%** 的立项门槛。两边共用同一个真实 ETW 服务；Pane 只更换了最小卡片宿主，并未复刻完整业务。这足以支持试迁，不能承诺正式版节省同样多。初始阶段 CPU 未显示优势；交互耗时因测量端点不同不能横比。

迁移版真实三卡宿主已在隔离桌面跑三轮：Pane 无卡、三卡常驻、总览打开分别为 **73.1、82.8、89.0 MiB** 私有工作集。追加三组 A/B 复测：排除每 8 ms 的测试文件轮询后，三卡常驻宿主短时 CPU 中位数由 **0.976%** 变为 **0.104%**（占整机），私有工作集为 **82.53 MiB**。这些样本仅有网卡采样，不含进程级 ETW 服务，不与 Galaxy 整组相减。正式性能验收仍待完成。

隔离 Windows 总览开合 100 次已复测：总览改为关闭时释放卡片内容、重开时复用 Pane 窗口。总句柄从首次关闭后的 2,219 到第 100 次后的 2,210，合成句柄保持 56 个，三张常驻卡片窗口和源文件不变。两小时常驻、实际屏幕闪烁及 ETW 整组对照仍待验收。

从独立迁移预览包的载荷取出应用，在隔离 Windows 桌面无测试轮询常驻三卡 305 秒。私有工作集中位数 **84.00 MiB**，CPU 占整机 **0.081%**，首末句柄数为 **2,191 → 2,187**；核对同一组三个可见窗口、设置与内容哈希，进程正常退出。此数据不含 ETW 服务，也不替代两小时验收。

| 资产 | 预览包证据及发布待办 |
| --- | --- |
| 流量服务 | 内层 ZIP 共 59 项，ZIP 摘要与随包清单一致。31 个 DLL 条目中，`Pane.Traffic.Core.dll` 为本地构建，其余 30 个按 SHA-256 对应 24 个 NuGet 包。只有 12 个包带独立通知文件；未携带通知的 12 个包括 TraceEvent 4.0.0、Microsoft.Data.Sqlite.Core 10.0.14 和四个 SQLitePCLRaw 2.1.13 包。发布前需核对对应版本的原始许可和通知；TraceEvent 随带的 `KernelTraceControl.dll`、`msdia140.dll` 另核对来源及分发条件，不能只看外层 NuGet 的 MIT 声明。 |
| 原生截图 | 外层 `NativeCapture/` 含 `ScreenCapture.exe` 和七份许可文件，已有来源锁和第三方清单。该目录没有 OCR 运行时。 |
| OCR 与离线词典 | 外层 278 项中没有 `NativeOcr/` 或 `DictionaryData/ecdict.sqlite`。已有本地预览不代表随包可用；正式交付前分别确定引擎、模型和词典的数据来源、版本与分发方式，再验收干净安装。 |

这是实物清单，不是分发许可结论，也不把内测包标为可发布。

源码构建的 OCR 使用锁定版 ImageReader `ImageReader/Res` 中的检测和识别模型，资源脚本将两者嵌入 `ImageReader.exe`。两份文件与锁定版 TinyOCR `Models` 中的同名文件分别逐字节一致。`src/Pane.Capture/sources.lock.json` 记录文件名和 SHA-256；源码构建在编译前拒绝模型缺失、额外文件或摘要不一致。

2026-11-20 从 RapidAI 的 ModelScope 模型库 `RapidAI/RapidOCR` 的 `v3.10.0` 下载 [检测模型](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/onnx/PP-OCRv6/det/PP-OCRv6_det_tiny.onnx) 和 [识别模型](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/onnx/PP-OCRv6/rec/PP-OCRv6_rec_tiny.onnx)。实际下载的 SHA-256 与发布方清单及 Pane 锁文件逐项一致；[同一版本模型卡](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/README.md) 标注 Apache License 2.0。这证明两份嵌入权重的来源，并记录了发布方对这两份模型的许可声明；正式随包仍须补齐模型归属、许可全文和适用通知。

引擎授权另算：锁定的 ImageReader 源码包含版权声明，ImageReader 和 TinyOCR 的源码树都未找到覆盖其自有代码的公开再分发许可。Clipper2 等依赖的源码许可不能替代这两项，Galaxy 预览包的授权记录也不自动覆盖 Pane fork。现阶段不启用标准包的 OCR；需先取得覆盖 Pane 分发的授权，或替换为有明确许可且能通过同一 OCR 工作流验收的引擎。

## Fork 安装与更新身份（待确认）

建议 fork 按独立产品安装，保留 Pane 的界面风格和模块架构，不默认覆盖或读取原版 Pane。另选安装目录不等于隔离：

| 边界 | 当前行为与交付要求 |
| --- | --- |
| 安装与用户数据 | `SetupPaths` 默认用 `%LOCALAPPDATA%\Programs\Pane` 和 `%APPDATA%\Pane`；`SetupIntegration` 和 `WindowsStartupRegistry` 仍用 `Uninstall\Pane`、`Pane.lnk` 和名为 `Pane` 的开机启动项。即使另选安装目录，仍可能覆盖或删除原版注册项与快捷方式。`SetupInstallPath` 还会以 `app\Pane.App.exe` 的存在接受非空目录；fork 要在写入前核实目标确属自身，选到原版目录应拒绝。安装器、卸载器、维护助手和脚本统一产品标识，包括卸载日志；不自动导入原版数据。 |
| 运行时 | `SingleInstance` 按 Windows 用户、生产/开发模式和测试实例标识生成互斥锁与管道名，不按安装路径区分。同一用户运行两个生产版本时，打开和退出指令可能转发给另一版；仅设置数据目录也不拆分实例。Fork 需隔离这些名字，给托盘和通知加可区分的产品名。安装器虽按完整路径检测进程，停止仍用 `--exit`，所以并跑时要验证退出指令只发给本产品。 |
| 全局输入 | 普通组合键走系统注册，已有失败提示；双击修饰键和全局鼠标手势走钩子，不走同一套注册冲突检查。若支持并跑，建议 fork 首次从托盘可用，让用户明确选择全局键、双击键和手势，不默认接管 `Win+V`。不能以两份配置各自显示启用来证明同一输入只触发一边。 |
| 更新与流量服务 | 迁移分支的实际应用不创建上游更新服务，不检查或下载，也不读取缓存后在启动时装上游版本；保留「关于」内的本地更新日志。独立渠道与发布签名就绪后再接入在线更新。流量服务的 SCM 名、管道和受保护目录要与 fork 标识一致，安装助手只识别本产品的载荷。 |

首版验收：在隔离 Windows 环境检查 fork 能独立安装、启动、配置快捷键和卸载，不覆盖原版 Pane。`-IsolatedPreview` 生成独立命名的 `Pane-Preview-*.exe`；外壳、应用安装进程、卸载程序和维护助手均要求 `--self-test-root` 指向临时目录直属的 `Pane-018-*` 目录，并拒绝自动更新安装。这只隔离安装测试路径，不等于可与原版 Pane 并存，也不适用于常规安装。

## 便签迁移顺序

1. **正文、预览和文件。** 预览复用 Pane 的原生 `MarkdownRender`，和历史、固定卡片共用同一份原文。可把 UTF-8 的 `.md` 或 `.txt` 导入为新便签，或把当前正文另存为文件；不建立同步、不写回导入源。现有渲染器覆盖标题、列表、表格、代码和 HTTP(S) 链接，不加载本地或远程图片，不等价于 Galaxy 的 HTML/公式输出。超长正文仍可编辑和另存，不生成大型预览。隔离 Windows 无障碍树实测标题、列表与链接渲染、切回编辑保留原文，退出后已保存便签哈希不变。系统文件对话框、取消和固定卡片同步仍需连贯验收。
2. **图片与版本。** Pane 用独立附件栏，不把图片或外部路径插入 Markdown 正文。支持选择 PNG 和从剪贴板粘贴图片，每条 4 张、每张最多 8 MiB 和 800 万像素；编辑器与版本历史显示附件，卡片显示首张。仍被当前便签或保留版本引用的图片不回收；模块备份包含这些图片，文本另存仍仅导出正文。附件落盘失败不改变便签草稿或正文。实体桌面的文件选择、取消和剪贴板粘贴仍待验收。
3. **提醒。** 从便签底部设置 10、15、30 分钟或 1、3 小时后的提醒，也可选本地下一个 18:00、明天 9:00，或输入 1 至 525600 分钟的自定义延迟。到达或超过 18:00 后，「下一个 18:00」指明天。Markdown 预览中可给未完成的任务行单独设提醒，同一便签的同名任务共用一个提醒，不影响整条便签的提醒。任务提醒使用设置时的文本，编辑或勾选任务不会取消，可在便签底部的「已设任务提醒」中取消。两类提醒共用单一计时器；错过的提醒在下次启动后补发，到点弹窗显示任务并可打开对应便签，删除便签一并取消。暂不支持重复、任意指定日历时刻或提醒随备份迁移。新增菜单、实际弹窗和休眠唤醒仍待 Windows 验收。

   便签列表用 Pane 的计时图标标记有提醒的条目，鼠标悬停与辅助技术可读到该便签及其任务中最早的提醒时间。修改、取消或触发时只刷新对应行，不重建列表；提醒菜单也显示当前作用域的时间。已有便签历史和提醒存储专项 27 项通过。Windows 界面仍需检查筛选、到期后切换到下一条、取消最后一条、列表焦点和长标题。

4. **回收站。** 删除已保存的便签后，可从便签窗口右上角打开回收站；恢复时保留正文、分类、图片和历史版本，不恢复原有桌面固定和提醒。从回收站永久删除需要再次确认。便签备份包含回收状态及关联文件。便签历史专项 22 项、便签备份专项 13 项通过，覆盖重启、恢复、永久删除和备份导入。回收站界面与桌面卡片联动仍待 Windows 点测。

## 剪贴板迁移顺序

图文合并结果和普通图片共用「图片」筛选规则；合并结果依然可按文本检索。图文合并专项 14 项通过，覆盖删除源图片后重启读取；富文本 21 项和备份 83 项通过，未操作系统剪贴板。实际筛选交互待 GPT-6.1 Terra 验收。

1. **验收现有回贴。** 文件路径、PNG、Unicode 文字仍按原顺序选择主类型。文字类条目可在同次采集中保留 HTML、RTF，同时保留纯文本供列表搜索和纯文本回贴。排除标记和来源过滤仍先于正文读取；每种富文本上限 256 KiB，历史原始格式共 8 MiB，超额只放弃原始格式，优先保留已固定及较新的条目。仅文字备份不带原始格式，含图片的备份同时包含保留的富文本。8 项富文本专项、55 项原生边界检查和 82 项备份回归通过；当前 Windows 会话拒绝建立独立窗口站，未触碰真实剪贴板，也未验收目标应用的格式和焦点。

## OCR 迁移顺序

1. **统一入口与结构化结果。** 截图框选、截图历史和剪贴板图片共用离线识别任务。Pane 读取同一次任务的文本、行框、字符框和识别用 PNG。真实引擎对 820 × 235 的合成中英文图返回 3 个行框和 18 个字符框。11 项专项检查覆盖会话、尺寸、点位、行尾换算和无可靠字符框时的整行选择。
2. **原图选字。** Pane 原生二级面板同时显示原图与识别文本；有效的字符框对应单字或字组，无可靠字符框时仅在有效行框内选择整行。不按行宽猜测字的位置。NativeAOT 构建通过；隔离 Windows 从截图历史调用实际引擎，确认同屏显示原图与中英文结果，存在复制全文及选中文字入口，原图哈希不变且临时会话清理。物理鼠标点选、不同 DPI 的对齐和实际剪贴板写入未测。

   原图已支持双向拖选和 Shift 扩选，按识别阅读顺序同步文本选区。测试覆盖换行、非 BMP 字符、选择首尾和不把邻近未选字框入，以及缺字符坐标时的整行回退。修订后的文本与原文不同则不应用原图坐标。还可用原生滚动容器平移、放大至适合窗口时的 4 倍或一键适应窗口。原图与选区共享同一缩放层，预览解码限制最长边 1,600 像素，不修改保存的原图、识别结果或字符坐标。真实缩放、鼠标选字及复制由 6.1 Terra 验收。
3. **历史与修订。** 截图面板的「识别记录」单独管理归档，不依赖截图历史和 OCR 临时会话。识别成功后，原图和结果只留在当前面板，点保存才归档；截图和剪贴板图片默认都不自动保存。最多保留 50 条手动保存的记录，不自动删除旧记录。每条保留原始识别和最近 10 次修订；旧稿可先预览、再保存为新修订。修订文本不套用原识别坐标，恢复原文可继续图上点选。「设置 → 数据」可单独导出和导入已归档的原图、识别结果和修订，不包含临时会话。合并保留本机同 ID 记录，超过 50 条时不应用导入；覆盖只替换这一个分区。

   删除时先将完整记录移出历史，再清理文件。遇到只读文件或无法移走时，原图、识别结果和修订均保留；失败直接提示，后续归档不会补删。Windows 识别历史 7 项验证了文件锁及只读、失败后继续读取、解除限制后手动删除；删除按钮与失败提示待 GPT-6.1 Terra 验收。
4. **识别后操作。** 识别结果和已归档修订稿的操作菜单提供复制所选、离线查词、AI 翻译和保存为新便签，保留单独的复制全文按钮。后三项有选区时只使用选中文字，无选区时使用全文；仅显式选择 AI 翻译时才会把文本交给已配置的翻译服务。保存便签不会写入剪贴板或改动识别记录。实际窗口验收需覆盖原图点选后打开菜单、全文回退、目标模块停用和修订稿。
5. **随包验收。** 引擎与模型正式随包仍需核对来源与通知；在干净安装里用三种真实入口验收，并分开测模型冷启动和连续识别后空闲占用，再决定是否需要常驻识别进程。

- **明确“历史”的写盘和清理范围。** 目前分时段字节与覆盖记录、应用运行累计是两类数据，都可能写入 `history.db`。现有「清空历史」只清当前账号的分时记录与覆盖，不清运行累计；日分辨率记录的保留规则是 730 天，不直接当新产品默认值。若提供「仅实时、不保存历史」，不能只关分时段写入而继续保存运行累计；实时所需累计可留内存，验收时同时检查两类记录和检查点。清理旧记录的范围需在用户确认前明确。

## 流量服务安装与验收

当前预览包只校验并携带 ZIP；安装外壳在解包前验证内层 ZIP 的摘要、逐文件摘要、路径、总大小和必需运行时文件。用实际预览载荷及拒收夹具通过 9 项检查，重新构建的 NativeAOT 外壳通过隔离安装、同版重装和卸载。此校验只确认包与随附清单一致，不证明发布者身份；不会将内层服务文件解包到磁盘、提权或注册服务。

独立流量安装助手已接入载荷预检。`build-preview.ps1 -WithSetupPreflight` 将 ZIP 和逐文件清单嵌入独立的 NativeAOT 可执行文件，并验证同一份内存载荷，不从当前目录或旁置文件读取。实际载荷可通过，内嵌的单文件摘要不匹配会被拒绝，旁置损坏清单不影响正确载荷，未知命令也被拒绝。可选 `-SetupSignerSha256` 固定发布证书，`--verify-release` 先验 Windows 信任链及实际签名证书，再检查内嵌载荷；无签名的预览不通过。签名由正式发布流程完成，未使用 Pane 正式证书验收。助手不在标准安装包内，不自行提权；验证命令不写盘。

独立流量助手可直接在终端运行，失败会将阶段和原因写入标准错误，原退出码和验签条件不变。NativeAOT 构建后，正常载荷通过，损坏清单报告摘要不匹配，未知命令显示用法，无签名的校验、暂存和安装均被拒绝；确认主安装器仍为图形入口，未注册服务。

新增 `--traffic-release-trust` 命令行专项，复用安装助手的 Windows 验签实现。使用带可信嵌入签名的 ONNX Runtime DLL 作为测试样本：正确证书通过，错误证书摘要、未签名文件和代码区被篡改的副本均被拒绝。嵌入测试证书摘要的未签名 NativeAOT 助手可通过 `--verify-payload`，但 `--verify-release` 仍返回 3。未改证书信任或注册服务；正式签名助手的隔离机首次安装、普通账号授权和真实 ETW 仍待验收。

`--stage-release` 在验签后要求管理员令牌，复用服务的 `DirectoryGuard` 创建版本暂存目录。重新检查落盘文件清单、权限和摘要后，才将目录改名为 `%ProgramData%\Pane\traffic\service\sha256-<digest>`。已有同摘要版本只验证复用，不原地覆盖。预检助手构建及载荷回归通过，未签名的暂存请求被拒绝且未创建服务目录；还需在隔离 Windows 环境用已签名助手验收实际落盘、同版本复用以及拒绝异常文件或权限的路径。

`--install-release` 使用当前管理员会话的 SID 手动首次安装。通过服务进程和管道身份校验后，还须用 Pane 共用的客户端成功查询该账号的 `own` 状态，才设为自启动。只读就绪检查不启用采集、不申请租约。隔离服务已验证共享请求正常返回，且不写入采集开关；无签名助手仍拒绝安装，未注册服务。代输管理员凭据、安装页接入及升级不在这个入口内；实际注册、采集和重连仍待验收。

首次安装前可用独立助手的 `--check-first-install` 核对发布签名、执行账号和提权状态、`PaneTraffic` 是否已注册，以及内嵌载荷 SHA-256。预检不暂存载荷、不修改授权、不启停或注册服务。最新 NativeAOT 助手以未签名载荷实跑：内嵌校验返回 0，预检与正式安装入口均返回 3，服务状态和数据目录状态不变。签名通过后的预检与真实安装仍需独立虚拟机和发布证书。

首次安装与正式服务启动共用授权文件的权限校验。只接受 SYSTEM 或 Administrators 所有且不向其它账号开放的文件；允许继承受保护数据目录的权限。现有记录必须是合法 SID 对应的 `own` 授权，无效文件不覆盖。Release 服务和 NativeAOT 助手构建通过；隔离验证了允许预期的继承权限、拒绝额外读权限及非受信所有者，并确认正式采集引擎在创建历史库之前拒绝不可信文件。签名助手的真实首次安装和普通账号读取仍待验收。

测试程序提供 `--traffic-service-check` 和 `--traffic-service-capture`，供签名安装后的隔离 Windows 测试机使用。前者在普通权限下核对正式服务身份和 `own` 状态；后者仅在测试账号的采集开关已关闭时运行，产生本机回环流量，核对双向字节是否归到探针的进程实例并持久化。探针结束后关闭该次采集，不清理历史或变更服务。测试程序 Release 构建、未安装时两条命令均返回 3 的检查、应用累计专项和实际合并包载荷的 9 项检查已通过；签名安装与真实采集分支未运行。测试机操作见 `src/Pane.Traffic/README.md`，卡片、多账号隔离和性能仍需单独验收。
